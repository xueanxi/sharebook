Python项目结构最佳实践指南

1. 项目结构标准

1.1 基础项目结构


my_project/
├── src/                    # 所有源代码放在src目录下
│   └── my_package/         # 主包名（与项目名相同）
│       ├── __init__.py
│       ├── core/           # 核心业务逻辑
│       │   ├── __init__.py
│       │   └── business.py
│       ├── api/            # API相关代码
│       ├── cli/            # 命令行接口
├── tests/                  # 测试代码
│   ├── __init__.py
│   ├── test_core.py
│   └── conftest.py
├── data/                   # 项目数据文件（大文件）
│   ├── raw/               # 原始数据
│   ├── processed/         # 处理后的数据
│   └── external/          # 外部数据源
├── docs/                   # 文档
├── scripts/               # 可执行脚本
│   ├── start_dev.py       # 开发环境启动
│   └── start_prod.py      # 生产环境启动
├── .env.example           # 环境变量示例
├── .gitignore
├── pyproject.toml         # 项目配置（优先使用）
├── README.md
└── LICENSE


1.2 禁止的文件/目录

• ❌ 不要在项目根目录放Python模块文件

• ❌ 避免main.py在根目录（应放在src或scripts中）

• ❌ 不要使用sys.path.append硬编码路径

• ❌ 避免复杂的相对路径导入（如....module）

1.3 多入口模块项目结构（特殊情况）

对于具有多个独立可运行模块的项目：

my_project/
├── src/
│   └── my_package/
│       ├── services/           # 各个独立服务模块
│       │   ├── service1/
│       │   │   ├── main.py     # 服务1的独立入口
│       │   │   ├── core.py
│       │   │   └── utils.py
│       │   ├── service2/
│       │   │   ├── main.py     # 服务2的独立入口
│       │   │   └── ...
│       │   └── ...
│       └── ...
├── scripts/
│   └── start_all.py          # 批量启动脚本
└── ...

允许的特殊情况：
• ✅ 每个服务模块可以有自己的main.py作为独立入口
• ✅ 服务模块内的main.py可以直接运行该特定服务
• ✅ 可以使用统一的启动脚本管理多个服务

from pathlib import Path

def get_data_path():
    """获取数据目录路径，兼容开发和生产环境"""
    current_file = Path(__file__).resolve()
    
    # 开发环境：从项目根目录查找
    if (current_file.parent / '../../data').exists():
        return current_file.parent / '../../data'
    
    # 生产环境：使用环境变量或默认路径
    data_dir = Path(os.getenv('DATA_DIR', '/var/data/my_project'))
    return data_dir

9. 注意事项

9.1 强制规则

1. 所有源码必须在src目录下
2. 使用pyproject.toml而非setup.py
3. 开发时使用pip install -e .
4. 禁止在模块中修改sys.path
5. 使用绝对导入或相对导入，禁止路径黑客
6. 多入口项目中，每个服务模块可以有自己的main.py作为独立入口
7. 服务模块的main.py应使用标准的if __name__ == "__main__":模式

9.2 常见错误示例

# ❌ 错误示例1：根目录模块
# 文件：project_root/main.py
import some_module  # 可能找不到！

# ❌ 错误示例2：路径黑客
import sys
sys.path.append('/some/random/path')  # 禁止！

# ❌ 错误示例3：复杂相对导入
from ....utils.helpers import something  # 难以维护！

# ✅ 正确做法：标准导入
from sharebook.utils.helpers import something


9.3 AI助手注意事项

当为该项目生成代码时，请确保：
1. 所有新模块放在src/sharebook/相应子目录中
2. 导入使用包名（sharebook.module）而非相对路径
3. 数据文件访问使用推荐的importlib.resources或路径解析器
4. 遵循现有的项目结构和命名约定
5. 对于多入口服务模块，保持每个服务的main.py独立性和完整性
6. 服务模块间的依赖应通过sharebook包进行，避免直接跨模块导入

此文档应作为项目结构的标准参考，所有新代码必须符合这些规范。
